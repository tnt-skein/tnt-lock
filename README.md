# tnt-lock

Кластерный замок тяжёлых операций для Tarantool: ключ в etcd,
привязанный к аренде. Снимок, уборку мусора, перебалансировку под одним
именем в каждый момент запускает один узел, а узел, упавший с замком
в руках, отпускает его без чужого участия.

```lua
local etcd = require('tnt.etcd.client')
local lock = require('tnt.lock')

lock.configure({ client = etcd.new({ endpoints = { 'http://127.0.0.1:2379' } }), identity = box.info.name })
lock.start()

lock.guarded('snapshot', function()
    return box.snapshot()
end)
--> 'ok' — снимок снял этот узел
--> nil, 'замок занят: snapshot' — его снимает другой узел
```

Зависимости: `tnt-fencing` (срок держания), `tnt-loop` (такт
продления), `tnt-clock` (часы), `tnt-log` (журнал), `tnt-must` (бросок
исключения тела как есть) и `tnt-external` (подмена часов в проверках).
Клиент хранилища приходит аргументом: подойдёт клиент `tnt-etcd-client`
либо любой объект с тем же договором.

## Зачем

Каждая тяжёлая операция по отдельности переживаема, а все разом на всех
узлах превращают штатное обслуживание в аварию. Узлы друг о друге
не знают, и договориться им негде, кроме общего хранилища решений.
Пакет делает для этого пять вещей:

- **Замок держится арендой.** Продление прекратилось — хранилище
  снимает ключ само, и застрявший замок снимать руками не придётся.
- **Узел узнаёт о потере раньше хранилища.** Своим он считает замок
  срок аренды за вычетом шага продления, а не весь срок.
- **Отказ хранилища — не свободный замок.** Держатель, возможно, жив,
  и брать замок в ответ на отказ нельзя.
- **Чужой замок не снимается.** Узел, у которого срок вышел, отзывает
  свою аренду, а не удаляет ключ по имени: ключ мог стать чужим.
- **Замок отпускается, чем бы операция ни кончилась** — удачей, парой
  `nil, err` или исключением.

Замок рекомендательный: он бережёт от одновременного запуска, а не
от одновременного выполнения, и проверок на самом узле не заменяет.

## Установка

```sh
tt rocks install tnt-lock --server=https://tnt-skein.github.io/rocks
```

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-lock.git
cd tnt-lock && tt rocks make --server=https://tnt-skein.github.io/rocks
```

## Как пользоваться

| Вызов | Что делает |
|---|---|
| `configure(opts)` | Клиент, имя узла, префикс ключей, срок аренды и шаг продления |
| `guarded(name, body)` | Выполняет тело под замком и отпускает его |
| `occupy(name)` | Берёт замок и отдаёт способ отпустить — для работ, что кончаются позже вызова |
| `acquire(name)`, `release(name)` | Взять и отпустить |
| `holds(name)` | Держит ли узел замок прямо сейчас |
| `owner(name)` | Кто держит замок по мнению хранилища |
| `start()`, `stop()`, `running()` | Такт продления удерживаемых замков |
| `renew(name)`, `renew_all()` | Продлить аренду одного замка либо всех |
| `status()` | Настройки, удерживаемые замки, идёт ли продление |

Настройки: `client` обязателен; `identity` — `'неизвестный'`,
`prefix` — `'/app/locks'`, `ttl` — 60 секунд, `renew_interval` — треть
срока. Негодные бросают на строке вызывающего:

```lua
lock.configure({ client = client, ttl = 30, renew_interval = 30 })
--> app.lua:14: замку нужен положительный срок аренды и шаг продления меньше него, а не срок 30 и шаг 30
```

Замок не взят — ответ `false` (у `guarded` и `occupy` — `nil`)
и причина; занятость узнаётся по началу `замок занят:`, всё остальное —
отказ хранилища:

```lua
lock.acquire('snapshot')   --> false, 'замок занят: snapshot'
lock.acquire('snapshot')   --> false, 'аренда не взята: CONNECTION: …'
lock.owner('snapshot')     --> { identity = 'storage-001-a', operation = 'snapshot', since = 1790484551.68 }
```

Работы обслуживания `tnt-maintenance` принимают замок настройкой:

```lua
require('tnt.maintenance').jobs.configure({ occupy = lock.occupy })
```

## Проверки

```sh
make deps          # luatest, luacheck, luacov с cluacov, зависимости пакета и tnt-etcd-client в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
```

Покрытие строк — 100 %, убитых мутантов — 100 % (45 проверок,
84 мутанта). Хранилище подменяется двойником `tnt.etcd.double`
из `tnt-etcd-client`, часы — через `_set_source`: сроки двигает
проверка, а не настоящие секунды. Примеры документа прогнаны
на etcd 3.5.
