# Кластерный замок

`tnt-lock` — замок тяжёлых операций на весь кластер: ключ в хранилище
решений (etcd), привязанный к аренде. Снимок, уборку мусора,
перебалансировку под одним именем в каждый момент запускает один узел,
а узел, упавший с замком в руках, отпускает его без чужого участия.

```lua
local etcd = require('tnt.etcd.client')
local lock = require('tnt.lock')

lock.configure({ client = etcd.new({ endpoints = { 'http://127.0.0.1:2379' } }), identity = box.info.name })
lock.start()

lock.guarded('snapshot', function()
    return box.snapshot()
end)
--> 'ok' — снимок снял этот узел
--> nil, 'замок занят: snapshot' — его снимает другой узел
```

Зависит от [`tnt-fencing`](https://github.com/tnt-skein/tnt-fencing)
(срок держания), [`tnt-loop`](https://github.com/tnt-skein/tnt-loop)
(такт продления), [`tnt-clock`](https://github.com/tnt-skein/tnt-clock)
(часы), [`tnt-log`](https://github.com/tnt-skein/tnt-log) (журнал),
[`tnt-must`](https://github.com/tnt-skein/tnt-must) (бросок исключения
тела как есть) и [`tnt-external`](https://github.com/tnt-skein/tnt-external)
(подмена часов в проверках). Клиент хранилища приходит аргументом:
подойдёт клиент [`tnt-etcd-client`](https://github.com/tnt-skein/tnt-etcd-client)
либо любой объект с тем же договором (см. «Клиент хранилища»).

## Зачем пакет

Снимок на большой арене съедает диск и процессор, уборка мусора —
диск, перебалансировка — сеть. Каждая из них по отдельности
переживаема, а все разом на всех узлах превращают штатное
обслуживание в аварию. Договориться внутри узла нечем: узлы друг
о друге не знают, а оператор, нажавший «снять снимок везде», именно
этого и просит.

Пакет делает для этого пять вещей:

- **Замок держится арендой, а не навсегда.** Пока узел продлевает
  аренду, ключ существует и занять замок нельзя. Продление
  прекратилось — хранилище снимает ключ само. В аварию это и важно:
  снимать застрявший замок руками будет некому.
- **Узел узнаёт о потере раньше хранилища.** Своим узел считает замок
  срок аренды за вычетом шага продления, а не весь срок: подтверждение
  идёт по сети, и узел, считающий себя держателем до последней
  секунды, узнавал бы о потере позже хранилища.
- **Отказ хранилища — не свободный замок.** «Занят другим»
  и «до хранилища не достучаться» выглядят одинаково только для
  невнимательного кода. Во втором случае брать замок нельзя: держатель,
  возможно, жив и работает.
- **Чужой замок не снимается.** Узел, у которого срок держания вышел,
  отпускает замок отзывом своей аренды, а не удалением ключа по имени:
  к этому мигу хранилище вправе было отдать ключ другому.
- **Замок отпускается, чем бы операция ни кончилась.** Операция,
  уронившая узел в исключение, не оставляет кластер без обслуживания
  до конца аренды.

## Как пользоваться

### Настройка: `configure`

```lua
local etcd = require('tnt.etcd.client')
local lock = require('tnt.lock')

lock.configure({
    client = assert(etcd.new({ endpoints = { 'http://127.0.0.1:2379' } })),
    identity = box.info.name,   -- кто держит; попадает в запись замка
    prefix = '/app/locks',      -- где живут замки
    ttl = 60,                   -- срок аренды, секунды
    renew_interval = 20,        -- шаг продления, секунды
})
```

Обязателен только `client`. Умолчания: `identity` — `'неизвестный'`,
`prefix` — `'/app/locks'`, `ttl` — 60 секунд (столько идёт средний
чекпойнт, и столько же терпимо ждать освобождения после падения
держателя), `renew_interval` — треть срока. Ключ замка — `prefix`,
косая черта и имя: `/app/locks/snapshot`. У клиента etcd бывает
и свой префикс — тогда в etcd ключ лежит под обоими.

Своим узел считает замок `ttl - renew_interval` секунд после последнего
подтверждения: при умолчаниях — 40 секунд. Два подряд пропущенных
продления аренду ещё не отнимают, а узел к этому мигу уже знает, что
держать замок дольше нельзя.

Негодные настройки — ошибка программиста: бросок на строке
вызывающего, и прежние настройки остаются в силе.

```lua
lock.configure({ ttl = 60 })
--> app.lua:12: замку нужен клиент хранилища решений

lock.configure({ client = client, ttl = 30, renew_interval = 30 })
--> app.lua:14: замку нужен положительный срок аренды и шаг продления меньше него, а не срок 30 и шаг 30
```

Место в броске — строка вызова `configure`, а не строка внутри замка.

Шаг не меньше срока, нулевой или отрицательный срок отвергаются:
срока держания они не дают, и узел считал бы замок своим вечно, а
хранилище отдало бы его другому между продлениями.

Повторная настройка забывает взятые замки, не отпуская их: они
освободятся по истечении аренды.

### Под замком: `guarded`

```lua
local answer, err = lock.guarded('snapshot', function()
    return box.snapshot()
end)
--> 'ok', nil
```

`guarded(name, body)` берёт замок, выполняет тело и отпускает замок,
чем бы тело ни кончилось. Замок не взят — тело не выполняется,
ответ — `nil` и причина:

```lua
lock.guarded('snapshot', body)   --> nil, 'замок занят: snapshot'
```

Отказ тела — та же пара `nil, err`, и она выходит наружу как есть:
вызывающий разбирает отказ замка и отказ операции одинаково.

```lua
lock.guarded('snapshot', function()
    return nil, 'диск кончился'
end)
--> nil, 'диск кончился'
```

Исключение тела выходит тем же, каким его бросили, — без приписки
места внутри замка, которая увела бы искать поломку не там. Замок
к этому мигу уже отпущен:

```lua
pcall(lock.guarded, 'snapshot', function()
    error('снимок не задался', 0)
end)
--> false, 'снимок не задался'
lock.holds('snapshot')   --> false
```

### Взять и отпустить: `acquire`, `release`, `holds`

```lua
lock.acquire('reclaim')   --> true
lock.acquire('reclaim')   --> true — свой замок, вторая аренда не берётся
lock.holds('reclaim')     --> true
lock.release('reclaim')   --> true
lock.release('reclaim')   --> false — замок не держится
```

`acquire(name)` берёт аренду на `ttl` и создаёт ключ с условием «его
ещё нет»: занявший первым держит замок, остальные уходят ни с чем.
Проигравший отзывает свою аренду сразу, а не оставляет её висеть
до конца срока. Ответ — `true` либо `false` и причина:

| Причина | Что случилось |
|---|---|
| `замок занят: snapshot` | Ключ занят другим узлом |
| `аренда не взята: …` | Хранилище не выдало аренду: недоступно, отказало |
| `замок не взят: …` | Аренда выдана, а ключ не создан по причине, отличной от занятости |

После двоеточия — отказ клиента как есть:

```lua
lock.acquire('snapshot')
--> false, 'аренда не взята: CONNECTION: POST http://127.0.0.1:1/v3/lease/grant: сервер не ответил: Could not connect to server (код 595)'
```

Свой замок, взятый повторно, — удача, а не отказ: вызывающий судит
по ответу, и `false` отправил бы его ждать собственный замок. Замок,
у которого срок держания вышел, берётся заново: прежняя аренда
отзывается, берётся новая, и если ключ за это время занял другой
узел, попытка честно ему проигрывает.

`release(name)` отпускает замок: `true`, если узел его держал. Пока
срок держания идёт, ключ удаляется и аренда отзывается — двумя
запросами, чтобы замок освободился, дойди до хранилища хотя бы один.
Срок вышел — только отзывается аренда: ключ, возможно, уже чужой, а
свой хранилище снимет вместе с арендой. Отказ хранилища здесь
не беда: аренда истечёт сама, и замок освободится — просто позже.

`holds(name)` — держит ли узел замок прямо сейчас. Ответ опирается
на время последнего подтверждения, а не на то, что ключ когда-то был
занят: между потерей связи и концом срока держания узел ещё вправе
считать замок своим, а после — уже нет, даже если в хранилище ключ
ещё его.

### Занять под работу: `occupy`

```lua
local release, err = lock.occupy('export')
--> function — замок взят; зовите release(), когда работа кончится
--> nil, 'замок занят: export'
```

`occupy(name)` — тот же захват, но вместо тела он отдаёт способ
отпустить. Нужен работам, которые кончаются позже вызова: работа идёт
в своём файбере и отпускает замок сама. Договор тот же, что у работ
обслуживания [`tnt-maintenance`](https://github.com/tnt-skein/tnt-maintenance),
и кластерный замок встаёт туда настройкой:

```lua
local maintenance = require('tnt.maintenance')

maintenance.jobs.configure({ occupy = lock.occupy })

maintenance.take_snapshot()
--> { accepted = false, job = 'snapshot', err = 'замок занят: snapshot' } — снимок снимает другой узел
```

### Продление: `start`, `stop`, `renew`, `renew_all`

Без продления замок живёт ровно одну аренду: чекпойнт на большой арене
идёт дольше, и хранилище отдало бы замок другому посреди работы.

```lua
lock.start()     -- такт продления всех удерживаемых замков раз в renew_interval
lock.running()   --> true
lock.stop()
```

Такт один на процесс и продлевает все замки узла: операций у узла
бывает несколько, а аренда у каждой своя.

`renew(name)` продлевает аренду одного замка:

```lua
lock.renew('snapshot')   --> true
--> false, 'аренда не продлена: …' — запрос не прошёл, замок пока свой
--> false, 'аренда истекла' — хранилище уже сняло ключ, узел забывает замок
--> false, 'замок не взят'
```

Неудачный запрос замок не отнимает: право держать его отмеряется
сроком, а не успехом одного запроса. `renew_all()` продлевает все
замки и отдаёт по алфавиту те, которых узел лишился: аренда истекла
либо продление не прошло, а срок держания уже вышел.

```lua
lock.renew_all()   --> {} — все на месте
lock.renew_all()   --> { 'snapshot' }
```

### Кто держит: `owner`

```lua
lock.owner('snapshot')
--> { identity = 'storage-001-a', operation = 'snapshot', since = 1790484551.68 }
lock.owner('export')     --> nil — замок свободен
```

Запись замка — JSON с именем узла, именем операции и стенным временем
захвата: без неё оператору остаётся гадать, чьей работы он ждёт.
Пустота означает «свободен», отказ — «неизвестно», и путать их нельзя:
решения по ним противоположные.

```lua
lock.owner('snapshot')
--> nil, 'CONNECTION: POST http://127.0.0.1:1/v3/kv/range: сервер не ответил: Could not connect to server (код 595)'
lock.owner('snapshot')
--> nil, 'запись замка не разобрана' — в ключе не JSON-объект
```

### Что с замками: `status`

```lua
lock.status()
--> { prefix = '/app/locks', identity = 'storage-001-a', ttl = 60, renew_interval = 20,
-->   held = { 'snapshot' }, running = true }
```

Сроки отдаются вместе с держаниями: по одному списку имён не видно,
сколько узлу осталось до потери замка. `held` — по алфавиту.

### Журнал

| Уровень | Запись | Когда |
|---|---|---|
| `info` | `операция пропущена: замок не взят` | `guarded` не выполнил тело; поле `err` — причина |
| `warn` | `замок потерян, а операция идёт` | Такт продления узнал о потере замка; поле `operation` |
| `warn` | `продление замков не отработало` | Такт упал; поле `err` |

Запись о пропуске говорит «не взят», а не «занят»: причина бывает
и отказом хранилища. Потерянный замок записывается, потому что прервать
идущую операцию нельзя, а делать вид, что ничего не случилось, тоже:
замок ушёл, и второй узел вправе начать ту же работу.

### Клиент хранилища

Замок зовёт у клиента шесть методов, все — парой «ответ, отказ»:

| Метод | Ответ | Отказ, который замок различает |
|---|---|---|
| `lease_grant(ttl)` | `{ id = … }` | — |
| `txn_create(key, value, lease_id)` | что угодно, кроме `nil` | `category = 'CAS_CONFLICT'`: ключ уже есть |
| `lease_keepalive(lease_id)` | что угодно, кроме `nil` | `category = 'LEASE_EXPIRED'`: аренда истекла |
| `lease_revoke(lease_id)` | не читается | — |
| `delete(key)` | не читается | — |
| `get(key)` | `{ value = … }` либо `nil` — ключа нет | — |

Отзыв аренды обязан снимать ключи, что на ней держатся: на этом стоит
отпускание замка, срок держания которого вышел. Клиент
[`tnt-etcd-client`](https://github.com/tnt-skein/tnt-etcd-client) этот
договор выполняет — так работает сам etcd. Его двойник
`tnt.etcd.double` сроков аренд не ведёт и ключей при отзыве не снимает:
в проверках ключ, который хранилище сняло бы само, убирают руками.

### Подмена в проверках: `_set_source`

Код поверх замка проверяется без etcd — двойником хранилища и своими
часами. Часы — внешние зависимости замка (`monotonic`, `realtime`),
и `_set_source` подменяет названные:

```lua
local double = require('tnt.etcd.double')

local now = 1000
local client, state = double.new()

lock._set_source({ monotonic = function() return now end })
lock.configure({ client = client, identity = 'storage-001-a', ttl = 60 })

lock.acquire('snapshot')   --> true
now = now + 39
lock.holds('snapshot')     --> true
now = now + 1
lock.holds('snapshot')     --> false — 40 секунд без подтверждения

lock._set_source(nil)      -- настоящие часы вернулись
```

## Чем пришлось поступиться

- **Замок рекомендательный.** Аренда может истечь, пока операция идёт:
  связь пропала, продление не дошло, хранилище отдало замок другому —
  а чекпойнт на этом узле продолжается, потому что прервать его нельзя.
  Поэтому замок бережёт от одновременного запуска, а не от
  одновременного выполнения, и не заменяет проверок на самом узле:
  работа с тем же именем не должна запускаться дважды и без него.
- **Запас на сеть — шаг продления.** Узел считает от мига, когда
  подтверждение пришло, а хранилище — от мига, когда получило запрос.
  Разница — время в пути, и её покрывает запас: срок держания короче
  аренды на шаг продления. Сеть, на которой ответ идёт дольше шага,
  этот запас съедает; шаг выбирают с оглядкой на неё.
- **Вложенных захватов замок не считает.** Повторный захват своего
  замка — удача, но счётчика нет: первый же `release` отпускает замок,
  и `guarded` внутри `guarded` с тем же именем отпустит его раньше
  внешнего. Одно имя — одна операция.
- **Одна настройка на процесс.** Настройки и держания живут в модуле,
  а не в экземпляре: два хранилища решений в одном процессе замок
  не обслуживает. Повторная `configure` забывает взятые замки,
  не отпуская их: через новое хранилище старые не отпустить, и они
  освобождаются по истечении аренды.
- **Срок аренды — целое число секунд.** etcd дробного срока не примет,
  а настройка его пропускает: отказ придёт первым же захватом,
  `аренда не взята: BAD_ARGUMENT: срок аренды должен быть целым числом
  секунд больше нуля`.
- **Причина отказа — строка.** `acquire` и `guarded` отвечают текстом:
  занятость узнаётся по началу `замок занят:`, всё остальное —
  отказ хранилища, и брать замок в ответ на него нельзя.
- **Отпускание после срока — только отзыв аренды.** Хранилище
  недоступно — ключ живёт до конца аренды, и замок освобождается
  позже, чем мог бы. Удалить ключ по имени здесь нельзя: чей он
  к этому мигу, узел не знает.

## Проверки

Проверки лежат в `test/` и идут на luatest: `make test`. Хранилище
подменяется двойником `tnt.etcd.double`, часы — через `_set_source`:
проверяется поведение замка, а не etcd, и сроки двигает проверка,
а не настоящие секунды. Такт продления проверяется настоящим файбером
на коротком сроке.

- захват, повторный захват своего замка, занятый ключ, отказ
  хранилища, проигравший отзывает аренду;
- срок держания и его граница, продление, истёкшая и непродлённая
  аренда, потерянные замки в `renew_all`;
- отпускание — своего замка и после срока, когда ключ занял сосед;
- `guarded` — удача, пропуск, отказ тела, исключение как есть;
- настройка — умолчания, отказы с местом вызывающего, граница шага;
- записи журнала о пропуске, потере замка и упавшем такте.

Проверок — 45; покрытие строк — 100 % (147 строк), убитых мутантов —
100 % (84 мутанта). Примеры этого документа прогнаны на etcd 3.5.
